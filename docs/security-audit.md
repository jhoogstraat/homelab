# Repository and security audit — 2026-10-10

Scope: every tracked repository file, deployment references, initialization/migration, backup/update recovery, host policy, container networking and privileges, encrypted secret handling, CI and documentation. Repository review was followed by read-only Pi inspection, public-DNS/Cloudflare-edge checks and selected live fixes. This is not a penetration test. See [remediation status](security-remediation.md) for what is actually deployed and what remains pending.

## Confirmed issues fixed

- **Rootful API exposure:** Traefik and Beszel previously mounted the unrestricted Podman socket and disabled container SELinux separation. They now use HAProxy on the internal `podman-api` network. The broker allows GET discovery/inspection/stats/events and GET/HEAD ping only. Mutation, exec, container logs/archive, image APIs and native Libpod paths are denied. There is no host-published API port. Only the broker retains direct socket access; it has a read-only root filesystem, no capabilities and no new privileges. This reduces client privileges; the broker remains a trusted host-control boundary. [Podman API security](https://docs.podman.io/en/latest/markdown/podman-system-service.1.html), [Traefik Docker security](https://doc.traefik.io/traefik/v3.6/reference/install-configuration/providers/docker/).
- **Proxy TLS and logging:** removed blanket backend certificate-verification bypass, unused dashboard/staging/plugin/metrics examples and empty middleware settings. Backend HTTPS now uses normal verification. INFO and journal access logs replace DEBUG and an unbounded persistent access-log file. Backends currently use their existing HTTP service ports on the private bridge; TLS to those backends is not added by this change.
- **Local state confidentiality:** preparation repairs application, credential and secret-generation parent directories to 0700. Recovery inventory and migrated credential directories are also private. The age identity must have restricted permissions and belong to the invoking root account. CLI maintenance requires root. Encrypted generation selection and device-owned configuration preservation remain intact.
- **Obsolete exposure/artifacts:** removed the retired WireGuard UDP firewall allowance, unused DDNS/InfluxDB ciphertext and unused root SSH public key. Removed obsolete Ansible ignore entries and dashboard/Traefik scaffolding. Migration compatibility and retired application archives remain intentional recovery functionality; they are not dead code.
- **Account/resource defaults:** Vaultwarden and Papra disable open registration. New AdGuard seeds restore the upstream rate limit of 20 queries/second; new Papra seeds limit uploads to 25 MiB. Existing application configuration can override these settings. Fresh installations need controlled initial-account bootstrap. [Vaultwarden configuration](https://github.com/dani-garcia/vaultwarden/wiki/Disable-registration-of-new-users), [Papra configuration](https://docs.papra.app/self-hosting/configuration/), [AdGuard security](https://adguard-dns.io/kb/adguard-home/running-securely/).
- **Build/CI:** host builds refresh and upgrade RPMs before layering packages. Actions are pinned to verified upstream commit IDs; checkout does not persist its token. Registry login/tag inputs use environment variables rather than shell-source interpolation, temporary registry credentials are removed even after failure, and test-only pushes trigger CI. SOPS development and image versions agree. Ignore rules prevent ordinary plaintext secret/key commits and exclude docs/tests from the host build context.

## Validation

All 24 lifecycle tests passed on Linux, including real rsync migration and real restic backup/restore. The final ARM64 image passed 13 bootc lint checks with only the existing nonempty `/boot/efi` Pi-firmware warning. All 17 packaged Quadlets passed generation/security assertions and systemd dependency verification, and the workflow passed actionlint. Bash syntax, local documentation links and YAML syntax checks passed; YAML lint retains line-length warnings for native templates/expressions. Gitleaks scanned the working tree and approximately 8.95 MB of all available Git history/checkpoint patches with redacted output: no findings. This is a scanner result, not proof that every credential is absent. All six retained encrypted dotenv files contain only encrypted application values, and every Quadlet secret reference resolves.

The real HAProxy policy passed 20 allow/deny cases in disposable ARM64 Linux containers, including API-version prefixes, mutating methods, archive/log access, Libpod paths and encoded/traversal paths. Fedora's packaged Quadlet generator accepted all definitions and translated the proxy dependencies correctly. These checks do not establish live client compatibility or radio/network behavior on the Pi.

## Remaining risks and deployment work

1. **Image vulnerability findings:** application images now use pinned digests; the Fedora base needs supported advisory coverage and upstream remediation. Automatic backups guard updates; they do not prevent vulnerable releases or prove database compatibility. Findings and scanner coverage must be reviewed before declaring the deployment clean. Third-party/custom application source is outside this repository.
2. **Prerelease host:** the configured Fedora 45 image identifies itself as a development/prerelease build. Existing documentation records this as an operator choice. A distribution change needs a separate tested boot/deployment decision; this cleanup does not silently downgrade the host.
3. **Trusted broker/metadata:** compromise of the API broker itself still grants rootful API access. Container inspection exposes environment metadata (including application secrets) to trusted clients on its network; Beszel's hub shares its agent's pod/network. Read-only socket mounts alone do not restrict API methods. The allowlist also intentionally disables Beszel container logs, image-update inspection and control actions. [Beszel API configuration](https://beszel.dev/guide/environment-variables).
4. **Hardware privilege:** optional Home Assistant, Matter and OTBR retain host networking and required network/device privileges. Home Assistant retains `spc_t` for hardware access. These are high-trust services, not fully isolated workloads. Verify actual host IPv4/IPv6 listeners, firewall zones and radio integrations on the device.
5. **Remote access/account policy:** Cloudflare tunnel routes/Access rules, router forwarding, DNS records, Cockpit accounts, MFA, effective application admin/registration settings and credential strength cannot be established from ciphertext and local files. Cloudflare changes and effective account settings are recorded in the remediation status. `jh` remains a trusted SSH-key administrator with passwordless sudo; root/password SSH login remains disabled.
6. **Persistent overrides:** bootc preserves `/etc`, and local Quadlets/drop-ins override image defaults. Firewall retirement, old decrypted secret generations and previously seeded settings require explicit device inspection. Removing Git ciphertext does not revoke provider tokens. Follow [the rollout procedure](operations.md#applying-the-repository-security-hardening), including backup, client compatibility, readiness and restore checks.
7. **Recovery limits:** the existing cold backup still stops applications for the full upload. Restic errors and incomplete snapshots block updates; readiness failure retains durable recovery intent. Independent backup credentials/password, remote storage protection and restore drills remain required. Live reboot/backup results and remaining recovery limits are recorded in the remediation status.

No issue-free or universally safe conclusion is warranted from these checks. The concrete hardening is reviewable in Git; remaining runtime and upstream risks are explicit.
